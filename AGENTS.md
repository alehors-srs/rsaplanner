# Ежедневник

## Проект

- Роль — разработчик личного облачного ежедневника с календарём, задачами, подзадачами и разделами.
- Исходники находятся в https://github.com/alehors-srs/rsaplanner.
- Рабочий сайт размещён в Cloudflare Worker `rsaplanner`, данные хранятся в D1.
- Сохраняй возможность переноса проекта на VPS с Node.js и SQLite.
- Подключение DeepSeek выполняется по отдельному запросу пользователя.

## Актуальная версия

- Перед доработкой читай актуальные файлы из ветки `main` репозитория. Если пользователь указал другую ветку, коммит или более свежие файлы, используй их.
- Указывай ветку и коммит, взятые за основу изменений.
- Для диагностики рабочего сайта учитывай, что последний коммит GitHub может ещё ожидать ручной публикации. Проверяй опубликованный коммит по успешному запуску GitHub Actions, если эти сведения доступны.
- Перед изменениями анализируй все связанные файлы, включая интерфейс, API, базу, конфигурацию и workflow.

## Порядок работы

1. Пользователь описывает желаемые изменения.
2. Предложи вариант реализации. Укажи файлы и номера строк, приведи код или фрагменты изменений, достаточные для оценки предложения.
3. После «ОК» реализуй согласованные изменения в актуальных исходниках.
4. Проверь синтаксис JavaScript, совместимость функций и побочные эффекты. Запусти доступные подходящие тесты. Сообщи о результатах и ограничениях проверки.
5. Пришли изменённые и новые файлы для скачивания, сохраняя пути внутри репозитория. Перечисли файлы и действия для их установки.
6. Пользователь самостоятельно загружает файлы в репозиторий.
7. Пользователь вручную запускает GitHub Actions для публикации в Cloudflare.

## Публикация и доступ

- Разрешение на запись в GitHub и самостоятельный деплой ассистенту не предоставлено. Готовь файлы для ручной загрузки пользователем.
- Workflow `.github/workflows/deploy.yml` запускается через `workflow_dispatch` и публикует только ветку `main`.
- Если подключён Cloudflare Workers Builds с автоматической публикацией из GitHub, для согласованного ручного процесса пользователь должен отключить его автоматические запуски.
- Cloudflare API token и Account ID задаются пользователем в GitHub Actions secrets.
- Пароль ежедневника `PLANNER_PASSWORD` хранится в секрете Worker.
- Секреты, рабочую базу и выгрузки личных данных храни за пределами репозитория.

## Данные

- Для изменений схемы добавляй отдельные SQL-миграции с учётом существующих записей.
- Для изменения базы включай в комплект инструкции по резервной копии, применению миграции и порядку публикации.
- Обычный workflow публикует код. Миграции рабочей D1 применяются отдельным действием по инструкции к конкретному обновлению.
