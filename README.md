# Ежедневник

Личный календарь, встречи, задачи и подзадачи. Один аккаунт, общая база на всех устройствах. Дата в календаре и крайний срок задаются отдельно. Подзадача с датой появляется в календаре и открывает карточку основной задачи. Даты и время отображаются как введены, а «Сегодня» определяется по часовому поясу устройства.

Интерфейс на HTML, CSS и JavaScript. API и SQL общие для Cloudflare Workers и Node.js. Для запуска на VPS используется встроенный SQLite в Node.js 24.

## Проверка на компьютере

Установите Node.js 24. Откройте PowerShell в папке проекта.

```powershell
npm run check
npm test
$env:PLANNER_PASSWORD = node -p "require('node:crypto').randomBytes(24).toString('base64url')"
$env:PLANNER_PASSWORD
npm start
```

Откройте [http://localhost:8787](http://localhost:8787). Логин — `planner`, пароль — значение переменной, которое PowerShell вывел перед запуском. Локальные записи сохраняются в `planner.sqlite`.

## Первый запуск на Cloudflare

1. Распакуйте архив и загрузите его содержимое в корень репозитория `alehors-srs/rsaplanner`. Включите файл `.gitignore`. База, выгрузки и пароль хранятся отдельно от репозитория.
2. Из папки проекта запустите `npx wrangler login`, затем `npx wrangler d1 create rsaplanner`. Скопируйте ID созданной базы в поле `database_id` файла `wrangler.jsonc`.
3. Выполните следующие команды:

   ```powershell
   npx wrangler d1 migrations apply rsaplanner --remote
   npx wrangler deploy
   npx wrangler secret put PLANNER_PASSWORD
   ```

   Последняя команда попросит ввести секрет. Сгенерируйте отдельный пароль командой `node -p "require('node:crypto').randomBytes(24).toString('base64url')"` и сохраните его в менеджере паролей. Подходят 24–128 символов из латиницы, цифр, дефиса и подчёркивания. До настройки секрета сервер отвечает кодом 503. Публикация использует секрет из Cloudflare при последующих деплоях.
4. Откройте HTTPS-адрес из вывода Wrangler. В системном окне браузера введите логин `planner` и пароль. Проверьте открытие на ПК и на телефоне через Wi‑Fi и мобильную сеть. Создайте запись на телефоне и откройте сайт на ПК. Если он уже открыт, вернитесь во вкладку или обновите её.
5. Если подключите Workers Builds к GitHub, назначьте `main` рабочей веткой и сохраните исправленный `wrangler.jsonc` в репозитории. Встроенные preview-адреса выключены. Для тестового стенда заведите отдельный Worker с отдельной D1 и паролем.

Сайт и API используют HTTP Basic поверх HTTPS. Браузер может запоминать вход на время своей сессии. При необходимости смените секрет в Cloudflare. Кнопка «Скачать данные» выгружает JSON со всеми разделами и записями. Для резервной копии с возможностью восстановления базы используйте SQL-экспорт.

## Перенос на AdminVPS

На время окончательного экспорта прекратите изменения в ежедневнике. С компьютера, где настроен Wrangler, выполните:

```powershell
npx wrangler d1 export rsaplanner --remote --output=./backup-planner.sql
```

Скопируйте SQL-файл и проект на VPS. На VPS установите Node.js 24 и утилиту `sqlite3`. Создайте новую базу из экспорта:

```bash
umask 077
sqlite3 -bail planner.sqlite < backup-planner.sql
sqlite3 planner.sqlite "PRAGMA integrity_check; PRAGMA foreign_key_check; SELECT count(*) FROM sections; SELECT count(*) FROM tasks;"
```

Используйте файл базы с новым именем, если `planner.sqlite` уже существует. В настройках службы Node задайте:

| Переменная | Пример |
| --- | --- |
| `PLANNER_ORIGIN` | `https://planner.example.com` |
| `PLANNER_DB` | `/var/lib/rsaplanner/planner.sqlite` |
| `PORT` | `8787` |
| `PLANNER_PASSWORD` | Отдельный случайный пароль из менеджера паролей |

Запустите `npm start` под отдельным системным пользователем с доступом к файлу базы и её каталогу. Для постоянного запуска используйте systemd. Приложение слушает только `127.0.0.1`. На VPS настройте внешний HTTPS через Caddy или существующий обратный прокси. Сначала проверьте, какие порты уже заняты AmneziaVPN. Если Caddy обслуживает нужный домен, достаточно блока:

```caddy
planner.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

После проверки количества записей, входа и редактирования на новом адресе переключите устройства на VPS. Сохраняйте резервные копии SQLite за пределами VPS.
